### LaraPaper Web UI accuracy — device-screen reconciler (2026-07-23)

Symptom: the Web UI device/dashboard preview showed a different screen than the
physical panel (e.g. morning-mashup while the panel showed the calendar). Cause:
the panel renders `/api/display` (the active playlist's active-item image) but
the Web UI shows `devices.current_screen_image`, which the sidecar wrappers
overwrite every cron run regardless of active mode (the calendar wrapper has no
mode gate; the morning-mashup wrapper runs outside its window), so the device
row drifts from the panel. Fix: `scripts/trmnl_reconcile_device_screen.sh`, cron
`* * * * *` on `khpi5`, sets the device row to the active playlist's served
image via the container's Laravel DB connection (no `sudo`, idempotent, quiet).
It touches no recipe and no working handoff path (so it cannot regress the
panel) and enforces playlist-as-source-of-truth (manual device-row overrides are
intentionally not persistent, per the orchestration model). Validated: a manual
run corrected `morning_mashup -> calendar`; an end-to-end test forced a clobber
and the cron self-healed within ~80s with no manual run. Legacy note: the
now-redundant per-wrapper device-row writes are left in place (zero regression
risk) for optional later removal.
